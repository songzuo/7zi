## 2. 测试现状分析

### 2.1 当前测试基础设施

**Vitest 配置** (`vitest.config.ts`):
- 环境: jsdom
- 并行化: forks (pool: 'forks')
- 超时: 15s (test), 10s (hook)
- 重试: 1 次 (flaky test 保护)
- 覆盖率: text, json, html

**Playwright 配置** (`playwright.config.ts`):
- 并行: 完全并行
- 重试: CI 环境 2 次
- 浏览器: Chromium (开发) / 全部浏览器 (CI)
- 超时: 10s (action), 20s (navigation)

### 2.2 已识别的测试问题

| 问题 | 严重度 | 说明 |
|------|--------|------|
| **覆盖率缺口** | 高 | lib/auth, lib/middleware, lib/monitoring 覆盖率偏低 |
| **Flaky 测试** | 中 | 部分 websocket 和 collab 测试不稳定 |

## 3. 测试策略

### 3.1 分层测试模型

```
┌─────────────────────────────────────────────────────┐
│                    E2E Tests                        │
│         (Playwright - 用户场景完整流程)              │
├─────────────────────────────────────────────────────┤
│               Integration Tests                      │
│           (Vitest - 模块间交互验证)                  │
├─────────────────────────────────────────────────────┤
│                 Unit Tests                          │
│           (Vitest - 函数/组件逻辑)                   │
├─────────────────────────────────────────────────────┤
│              Static Analysis                        │
│        (ESLint + TypeScript + Prettier)            │
└─────────────────────────────────────────────────────┘
```

### 3.2 测试金字塔

```
                    ▲
                   /E\
                  /2E \
                 / E2E \
                ─────────  (少量，聚焦关键路径)
               /I n t e g\
              /  Integration\
             ────────────────  (中量，覆盖模块交互)
            /  Unit  Tests   \
           /─────────────────\  (大量，聚焦代码逻辑)
          ─────────────────────
```

### 3.3 测试原则

1. **快速反馈**: 单元测试 < 5s，集成测试 < 30s
2. **稳定可靠**: 无 flaky test，或明确标记并重试
3. **独立执行**: 测试之间无依赖，可并行运行
4. **覆盖优先**: 关键路径 100% 覆盖
5. **维护成本**: 测试代码与生产代码同等重视
