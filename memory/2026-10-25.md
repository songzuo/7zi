
## T120 analytics 非法 body 500→400（已完成）

**提交**：`ab39579a6f`（metrics）、`8967d2bc5d`（export）、`3dcac4461a`（文档标注清理）

**根因 4 处**（metrics 路由 22 用例里 20 个失败，500 而非 200/400）：
1. 缓存替身 `get` 返回 `undefined`，路由用 `cached !== null` 判断命中 →
   `undefined` 被当成"命中"直接返回 → `timeSeries.data` 抛 TypeError。
2. `afterEach` 用 `vi.resetAllMocks()` → 连 mock 实现体一起清空 →
   全局 db 替身 `getDatabase()` 返回 `undefined` → `'queryRows' of undefined`。
3. 断言层级过时：`timeSeries`/`cacheStats` 是 `data` 子节点不是 `metrics` 子节点；
   `performance` 字段名 `responseTime` 不是 `apiResponseTime`；
   路由从未有 `logger.info('Analytics metrics fetched')` 与 `cacheInfo`。
4. 实现缺陷：body 解析失败落外层 catch → 500（应为 400）。

**教训（重要）**：
- 缓存未命中哨兵值必须是 `null`，`undefined` 会穿透 `!== null` 判断。
- `vi.resetAllMocks()` 会清实现体，`vi.clearAllMocks()` 只清调用记录——
  用 resetAllMocks 会让全局 mock 替身变成返回 undefined 的裸 mock。
- 排查"单独跑能过、一起跑就挂"时，先做**基线对照**（git checkout 父提交），
  再用最小复现文件隔离，比反复读代码快得多。
- Vitest 报告只显示断言不显示服务端错误：在 logger mock 里加 console.log
  打印 `error` 的 stack 是最快的定位手段。

**验证**：analytics 45 failed → **4 files / 87 tests 全绿 exit=0**；
analytics+tenant+auth+security **25 files / 619 tests 全绿 exit=0**；
`npx tsc --noEmit` exit=0；eslint 0 errors（3 warnings 既有）。
