### 真实实现 bug（生产代码，不是测试问题）
1. **`db.exec()` 多语句崩溃** — better-sqlite3 的 `exec()` 只支持**单条**语句，
   传多条会抛 `The supplied SQL string contains more than one statement`。
   `src/lib/db/user-preferences.ts` / `audit-log.ts` 都中招。改为循环逐条 exec。
   → 教训：全局 setup 的假库 mock 不抛错，把这类 bug 全掩盖了。
2. **连接池 FIFO → LIFO** — `release()` 刷新 `lastUsedAt`，FIFO 下"刚归还的连接"
   反而排到队尾，下次拿到冷连接。改为取 `lastUsedAt` 最大的（最热），保住 SQLite page cache。
3. **v3 迁移测试** — 真实 sqlite 下 `migrate()` 会跑全部 7 个版本，v6 需要 feedbacks 表。
   改为直接取 `MIGRATIONS.find(m => m.version === 3)` 调 `up()`，断言 v3 真实产出的 6 个索引。
   测试表缺 `wallet_transactions.currency` 列（v3 要建 currency,status 索引）→ 补上。
   `:memory:` 跨用例共享 → beforeEach 清库（先 `PRAGMA foreign_keys = OFF`）。

  `connection.ts` 的 exec() 用 `db.prepare()`，better-sqlite3 的 prepare
  不支持多语句（"The supplied SQL string contains more than one statement"），

  实际只是把调用方的多语句拆成了多次调用 —— 根因还在。
  真正的修法是 exec() 用原生 db.exec()（没有 params 时），
  或者按分号拆分。**读提交说明不能代替看 diff。**

- **commit message 里的反引号会被 shell 展开**：
  `git commit -m "... \`xxx\` ..."` 里写了 `` `const` `` 被当成命令替换。
  报错是 shell 的，但 commit 还是成功了，消息内容没坏。
  → 写长 message 用 heredoc 或单引号包裹。
