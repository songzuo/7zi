## 本轮真正修掉的东西：PAT 的三个落盘点（不止会话记录）

§53/§56 说 PAT 会明文躺在会话记录和 /tmp 脚本里。这次实测发现**三个落盘点**，
其中一个是我自己巡检命令造成的：

### ① 巡检命令自己就是泄漏源（§81）
```bash
TOK=$(grep -oE 'gh[p]_[A-Za-z0-9]{20,}' /root/.git-credentials | head -1)
grep -rl "$TOK" ...        # ← PAT 作为参数进 argv → OpenClaw 写进会话 .jsonl
```
反查命中的是**这次巡检自己**。同一轮扫第二遍会命中更多 —— 越查越多。
**修正**：改成 python 内部读文件比对，不把 token 传给命令行。

### ② journal 里的命中是 5 月的归档残留
```
May 07 07:46:09 bot6 node[986887]: | **环境变量泄露 GitHub Token** | `ghp_...`
```
**告警本身把 token 写进了日志**。
journal 是二进制，`sed -i` 会破坏结构 → 用**等长替换**（补齐到原长度），
保持文件大小与所有偏移不变，`journalctl --file=` 复核仍可读。

### ③ `.next` 构建缓存把 `GITHUB_TOKEN` 烤进磁盘（每轮构建复现）
```
7zi-frontend/.next/cache/turbopack/v16.3.8-*/00000026.sst
上下文: ...GITHUB_TOKEN(ghp_...)NODE_OP...
```
turbopack 快照了**构建当时的环境变量**。`.next` 在 .gitignore 里
（不进仓库）但**明文躺磁盘**，且构建 shell 带了 token → 每次构建复现。
**处置**：只移走 `cache/turbopack`，保留 BUILD_ID 与已构建产物
（本机 next-server 监听 **:3006**，不是 3000/3001，清完 curl 复核仍响应）。
**根治**：构建前 `env -u GITHUB_TOKEN -u GH_TOKEN npm run build`。

### 揪出的 4 个真缺陷

**1. P0 安全：敏感数据明文写进审计日志**
- `maskObject` 只查「完整路径」和「裸字段名」，**通配符在嵌套对象里完全失效**
  （`{ path: 'secret*' }` 对 `details.secretKey` 不生效）
- `maskChange` 只查通配符，**精确路径完全没查** ——
  而 changes 传进来的字段就是 `'password'`，配置里也正是 `'password'`
  → **变更记录里的新旧明文口令直接进审计日志**
- 修复：查找顺序补全为 完整路径 → 裸字段名 → 通配符(路径) → 通配符(裸名)

**2. event-builder 返回内部引用**
`build()` 把 details/tags/changes/metadata 的**同一批引用**交出去，
调用方改一次就污染了已存事件。→ 改成深拷贝。

**3. query-service 丢 filter**
`filter` 和 `options.timeRange` 是两套入参，原实现只认后者 ——
调用方传 filter 时查询条件直接丢失。

**4. storage 的 include* 开关不生效**
两个 storage 实现都忽略 `includeDetails/includeChanges/includeMetadata`，
"不要 details"照样返回全量。
