## 2026-10-25 05:15 · 全局 db 测试替身 5 处失真（提交 dd4ed233e9）

`src/lib/tenant/__tests__/tenant.test.ts` 的 20 条失败，我上一轮记为
「根因是全局 vi-mocks 的手写 SQL 引擎不支持通用 WHERE/IN/OFFSET」。
这一轮真正挖到底了 —— **不是能力不够，是替身在好几个地方根本是坏的**。

### 5 处失真（逐条定位，不是靠猜）

1. **缺 `db` 具名导出** → 替身只导出 getDatabase/getDatabaseAsync，
   而业务代码普遍 `import { db } from '../db'` → 模块 import 期就抛
   `No 'db' export is defined on the mock`，整个测试文件 0 用例。
2. **`exec` 不落库** → 只处理 CREATE TABLE，其余一律返回
   `{changes:1}` 且不写表 → 业务代码 INSERT 后 SELECT 不到行，
   表现为「创建成功但读回来是 null」。
3. **通用 WHERE 从未生效** → executeAll 只特判了 `workflow_id`，
   其余 `WHERE col = ?` 全忽略 → `SELECT * FROM plans WHERE id = ?`
   返回表里第一行，表现为「按 id 查不到 / 查到别人」。
4. **多行 SQL 解析失败（两处正则缺 `s` 标志）** — 这条最隐蔽：
   - `parseUpdateSets` 的 `/SET\s+(.+?)\s+WHERE/i` 不带 dotAll
     → 生产代码的多行 UPDATE **整条被静默跳过**（changes: 0），
     表现为「更新没生效」
   - 聚合查询的 `/SELECT\s+(.+?)\s+FROM\s+(\w+)/i` 同样缺 s
     → SELECT 段匹配失败 → 返回原始行，聚合字段全是 undefined
5. **缺数据库默认值 + 缺聚合函数** → INSERT 不补
   created_at/updated_at/recorded_at（真实 schema 有 DEFAULT CURRENT_TIMESTAMP）
   → `ORDER BY created_at DESC LIMIT 1` 排序随机、
   `WHERE recorded_at >= ?` 把行全过滤掉；
   只支持 COUNT(*)，不支持 SUM/AVG 与一条 SELECT 多个聚合
   → billing 的 getMonthlyUsage() 恒返回空数组

### 教训（值得记住）
**两份正则少一个 `s` 标志，等于整类多行 SQL 静默失效。**
生产代码写 SQL 几乎都用多行模板字符串，而替身的正则按单行假设写。
症状极具迷惑性：不报错、只是「更新没生效」「聚合是 undefined」。
→ 今后改这类替身，先 grep 有多少正则缺 `s`。

另外：`rowMatchesConditions` 原先把 undefined 丢进比较运算，
既可能抛错也可能因 NaN 语义产生「看起来通过」的假象 → 改为缺列直接不匹配。
