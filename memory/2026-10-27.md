## 15:50 【重要】TypeScript 错误清零 —— 一行根因修复（主管亲自定位）

### 根因（子代理全部猜错了）
`src/lib/undo-redo/middleware.ts` 里一条**坏的模块增强**：
```ts
declare module 'zustand/vanilla' {
  interface StoreMutators<S, _A> { ... }   // ← 参数名写成 _A
}
```
zustand 官方声明是 `interface StoreMutators<S, A>`（node_modules/zustand/vanilla.d.ts:23），
**TS2428 要求所有声明的类型参数完全一致**。
因为这是**全局模块增强**，一处声明非法 → `Mutate<>` → `ExtractState<S>` 全线失灵
→ **整个编译单元里所有 zustand store 的 `set(state => ...)` 都拿不到上下文类型**
→ 满屏 TS7006（隐式 any），且看起来"每��� store 各自坏掉"。

### 最小复现（我实测）
```ts
declare module 'zustand/vanilla' { interface StoreMutators<S, _A> { 'zustand/bad': { probe: number } } }
create<S>()(devtools((set) => ({ n:0, inc: () => { set((s) => ({n: s.n+1})) } })))
// → TS2428 + TS7006 's' implicitly any
```
去掉增强或把 `_A` 改成 `A` → 立刻干净。

**此前三个子代理的结论全是错的**：都猜是 "zustand v5 的 devtools 破坏上下文类型推断"。
实测 devtools/persist 单独用都完全干净（p1/p2/p3 三个探针全部 0 error）。
→ **教训：并发代理都在"改症状"（给每个 store 加 StateCreator 标注），没人去查那个"全局"信号。
   TS2428 是全局性的，它才是元凶。**

### 修复
`middleware.ts` 一行：`_A` → `A`，并加注释说明"改参数名会毒化全仓"。
