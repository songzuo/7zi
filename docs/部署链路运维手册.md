## 二、三个根因

### 根因 1：零 swap 的机器跑 next build（最致命）

```
Mem:  11959 total / 11601 used / 357 available
Swap: 0 total / 0 used          ← 关键
```

有 12G 物理内存但**没有任何 swap 缓冲**。`next build` 吃到内存上限后，
内核没有换页缓冲，只能直接 SIGKILL 进程 → sshd / nginx / pm2 被杀 →
表现为「端口可连但零字节响应」。

**判据（重要）**：这类故障**不是网络问题**。
- TCP 22/80/443 可连（`/dev/tcp` 探测通过）
- ping 正常（44~87ms）
- DNS 正常
- 但应用层零响应：SSH `Connection timed out during banner exchange` /
  `Connection reset by peer`，HTTP 0 字节

**修复（已落地）**：155 建 4G swapfile，写入 `/etc/fstab` 持久化，
并调 `vm.swappiness=20` / `vm.vfs_cache_pressure=50`。
判据：`swapon --show` 显示 `/swapfile 4G`。

### 根因 2：deploy 与 prod 两条链路共用同一目录 + 同一 build 锁 + 同一日志文件

109 上的两个裸库（`szspd-deploy.git` / `szspd-bare.git`）的 post-receive
都做 `git archive | tar -x -C /root/7zi-project`、都跑同一个 `next build`、
都写 `/tmp/szspd-deploy-hook.log`。

同时 push 必然自相残杀：
- 一条报 `Another next build process is already running`（Next 自带锁）
- 另一条成功，但**日志被覆盖**，事后无法判断到底哪个版本上线了

**修复（已落地）**：`scripts/build-guard.sh` 的 `lock` 子命令提供互斥，
拿不到锁就**跳过本次构建**（exit 2），旧版保持运行。

### 根因 3：tailwindcss 依赖缺失（构建真失败）

证据链：
1. `src/app/globals.css` 第 1 行：`@import 'tailwindcss';`（Tailwind v4 语法）
2. `package.json` 只声明 `@tailwindcss/postcss`（插件），**没有 `tailwindcss` 本体**
3. `node_modules` 是 pnpm 严格结构：`tailwindcss@4.3.3` 只存在于
   `node_modules/.pnpm/` 内，未提升到顶层 `node_modules/tailwindcss`
4. → `next build` 报 `Can't resolve 'tailwindcss' in '.../src/app'`

**修复（已落地）**：`package.json` 补 `"tailwindcss": "^4.2.2"`（与
`@tailwindcss/postcss` 成对，同版本号）。Tailwind v4 要求二者成对声明。

## 三、构建守卫（`scripts/build-guard.sh`）

三个子命令，已集成进全部三条 post-receive hook：

| 子命令 | 作用 | 退出码 |
| --- | --- | --- |
| `precheck <dir>` | 查内存可用 / swap / 磁盘 / 已有构建进程 | 0=通过，1=拦截 |
| `lock` | 构建互斥（flock 优先，缺失时退化为 mkdir 原子锁） | 0=拿到，2=跳过 |
| `report <dir>` | 固化现场：dmesg OOM 证据 / free / df / BUILD_ID 时间戳 | 0 |

### 阈值

```bash
GUARD_MIN_AVAIL_MB=1200    # 构建所需最小可用内存
GUARD_MIN_FREE_DISK=12     # 磁盘可用百分比
GUARD_TIMEOUT=1800         # 构建最长允许秒数
GUARD_LOCK_FILE=/tmp/szspd-next-build.lock
GUARD_REPORT_FILE=/tmp/szspd-build-guard-report.log
```

**设计原则**：内存不足时宁可**这次不部署**，也不要把整台生产机拖死。
不部署 = 旧版继续运行（可接受）；机器被拖死 = 全站不可用（不可接受）。

## 四、日常操作判据

### 部署前

```bash
# 1. 确认内存水位（关键：available，不是 used）
free -m | head -3
# 2. 确认没有构建在跑
pgrep -af "next/dist/bin/next build"
# 3. 确认 swap 已启用
swapon --show
```

### 部署后必查（缺一不可）

```bash
# 1. 构建成功标志（不要只看进程退出码）
grep -c "Compiled successfully" /tmp/szspd-hook-build.log   # 必须 > 0
# 2. 产物完整
ls -la .next/BUILD_ID .next/prerender-manifest.json
# 3. 进程正常（注意 restarts 与 uptime）
pm2 describe 7zi-shop | grep -E "status|restarts|uptime"
# 4. 冒烟（本地回环 + 公网）
for p in /shop /en /api/shop/currency; do
  curl -s -o /dev/null -w "$p -> %{http_code}\n" "http://127.0.0.1:3006$p"
done
```

### 判据表

| 现象 | 含义 | 处置 |
| --- | --- | --- |
| `Compiled successfully` 缺失 | 构建失败 | **不重启**，旧版保持；读 build 日志找 `Error:` 行 |
| `Another next build process is already running` | 并发自伤 | 守卫应已拦截；确认 hook 里有 `build-guard.sh lock` |
| pm2 `restarts` 持续上涨 + `uptime` 很短 | 进程反复崩溃 | 先查 `dmesg \| grep -i oom` |
| SSH banner 超时 + HTTP 0 字节 + ping 正常 | **内存耗尽，不是网络故障** | `free -m` 看 `Swap 0` → 建 swapfile；重启机器释放 |
| `7zi.com` 403 + 响应体 `Attention Required! | Cloudflare` | Cloudflare WAF 拦 curl 默认 UA | 加浏览器 UA 重试，与部署无关 |

## 五、换行符（.gitattributes）

部署用 `git archive | tar -x` 在 Linux 解包执行 hook 与部署脚本。
Windows 编辑的文件若带 CRLF，Linux 会报
`/usr/bin/env: 'bash\r': No such file or directory`，**post-receive 会静默失败**。

规则（主仓 `.gitattributes`）：
- `*.sh` / `*.bash` / `*.py` / `*.json` / `*.yml` / 源码类 → `eol=lf`
- `*.ps1` / `*.bat` / `*.cmd` → `eol=crlf`
- 图片 / 压缩包 → `binary`
