## 1. 根因分析

`withPerformanceLogging` 定义在 `src/lib/middleware/db-performance.ts:129`：

```ts
export function withPerformanceLogging(db: DatabaseConnection): DatabaseConnection
```

其中 `DatabaseConnection` 来自 `@/lib/db`（即 `src/lib/db/index.ts` → re-export 自 `src/lib/db/connection.ts`），其签名为：

```ts
export interface DatabaseConnection {
  query: (sql: string, params?: unknown[]) => unknown
  queryRows: <T = Record<string, unknown>>(sql: string, params?: unknown[]) => T[]
  get: <T = Record<string, unknown>>(sql: string, params?: unknown[]) => T | null
  exec: (sql: string, params?: unknown[]) => DatabaseResult
  prepare: (sql: string) => DatabaseStatement
  pragma: (name: string, options?: { simple: boolean }) => unknown
  getConnection?: () => unknown
  batch: (statements: Array<{ sql: string; params?: unknown[] }>) => Promise<DatabaseResult[]>
  paginate?: (sql: string, pagination: unknown, params?: unknown[]) => Promise<unknown>
  beginTransaction: () => void
  commit: () => void
  rollback: () => void
  isInTransaction: () => boolean
}
```

### 两个文件各自的失败原因

**`src/lib/db/connection.ts:363`（TS2345）**

本文件的 `baseConnection` 对象字面量中，`batch` 是**同步**实现，返回 `DatabaseResult[]`；而 `withPerformanceLogging` 的入参类型要求 `batch` 返回 `Promise<DatabaseResult[]>`。TS 报错：

```
The types returned by 'batch(...)' are incompatible between these types.
  Type 'DatabaseResult[]' is missing the following properties from type 'Promise<DatabaseResult[]>': then, catch, finally, [Symbol.toStringTag]
```

**`src/lib/db/index-unified.ts:360`（TS2345）**

本文件定义了**自己的**（更窄的）`DatabaseConnection` 接口——没有 `get` / `beginTransaction` / `commit` / `rollback` / `isInTransaction`，且 `batch` 返回 `Promise<DatabaseResult[]>`。而 `withPerformanceLogging` 要求的是 `@/lib/db` 那份**更宽**的接口。TS 报错：

```
Type '{ ...; batch: (statements: ...) => DatabaseResult[]; }' is missing the following properties from type 'DatabaseConnection': get, beginTransaction, commit, rollback, isInTransaction
```

### 共性

两处的 `catch` 分支早已使用 `as unknown as DatabaseConnection` 做显式兜底，但 **`try` 分支直接把 `baseConnection` 传给了 `withPerformanceLogging`，没有做同样的显式断言**，因此类型系统在这条路径上报 TS2345。

`src/lib/middleware/db-performance.ts` **不在本任务可改路径内**，且修法优先级 (a) 要求「不修改 `DatabaseConnection` 接口语义或 DB schema」——改该中间件文件的签名会波及 `src/lib/db/performance-logger.ts:185` 等其他调用方。因此采用修法优先级 (b)：**在调用处做与 catch 分支一致的显式断言**，运行时行为完全不变（断言是纯编译期操作）。

## 2. 改动清单（仅限授权的两个文件）

### `src/lib/db/connection.ts`（+5 / −1）

改动位于第 360–368 行（原 360–367 行），try 分支：

```diff
     try {
-      return withPerformanceLogging(baseConnection)
+      // The wrapper mirrors the DatabaseConnection contract, but its `batch` return type
+      // is declared as a Promise while the underlying implementation is synchronous.
+      // Use the same explicit assertion as the fallback branch below so both paths
+      // return a consistent DatabaseConnection.
+      return withPerformanceLogging(baseConnection as unknown as DatabaseConnection)
     } catch {
       return baseConnection as unknown as DatabaseConnection
     }
```

### `src/lib/db/index-unified.ts`（+7 / −1）

改动位于第 357–367 行（原 357–364 行），try 分支：

```diff
     try {
-      return withPerformanceLogging(baseConnection)
+      // The wrapper mirrors the DatabaseConnection contract, but the local
+      // DatabaseConnection type in this module is a narrower shape than the one
+      // the middleware is declared against. Use the same explicit assertion as the
+      // fallback branch below so both paths return a consistent DatabaseConnection.
+      return withPerformanceLogging(
+        baseConnection as unknown as Parameters<typeof withPerformanceLogging>[0]
+      ) as unknown as DatabaseConnection
     } catch {
       // Performance logging module not available, return base connection
       return baseConnection as unknown as DatabaseConnection
     }
```

**未改动**：`DatabaseConnection` 接口语义、`withPerformanceLogging` 实现、DB schema、tsconfig / package.json / vitest.config.ts / eslint 配置。

## 4. 遗留问题 / 建议

1. **`batch` 的同步 / 异步契约不一致（架构级遗留，超出本任务范围）**
   `src/lib/db/connection.ts` 的 `DatabaseConnection.batch` 在接口上声明为 `Promise<DatabaseResult[]>`，实际实现是同步返回 `DatabaseResult[]`。调用方 `src/lib/db/batch-operations.ts:138,448` 使用 `await db.batch(...)`，`await` 一个非 Promise 值虽不报错，但类型契约与运行时不一致。这是本次 TS2345 的深层根因。
   **建议**（需另开任务、且会触及 `src/lib/middleware/db-performance.ts` 与 `src/lib/db/batch-operations.ts`）：统一 `batch` 为异步实现，或把接口改为同步签名。本次任务严格遵守「不得修改 `DatabaseConnection` 接口语义」的硬约束，故未处理。

2. **`index-unified.ts` 与 `connection.ts` 各自定义了一份 `DatabaseConnection`**（前者更窄，缺 `get` / 事务四件套）。这直接导致两处报错形态不同。建议后续收敛为单一来源（`src/lib/db/connection.ts`），由 `index-unified.ts` 复用类型导出。本次同样受「不得修改接口语义 / 不得越界改他人文件」约束，未处理。

3. `src/lib/middleware/db-performance.ts` 位于本任务授权路径之外，未做任何修改。
