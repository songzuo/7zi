## 🔐 需要手动配置的变量（涉及密钥）

以下变量需要从第三方服务获取并手动配置：

| 变量名 | 服务来源 | 用途 | 紧急程度 |
|--------|----------|------|----------|
| `RESEND_API_KEY` | Resend | 邮件发送 | 🔴 高 |
| `CONTACT_EMAIL` | 手动设置 | 邮件接收地址 | 🔴 高 |
| `FROM_EMAIL` | Resend | 邮件发送地址 | 🔴 高 |
| `GITHUB_TOKEN` | GitHub | API 访问 | 🟡 中 |
| `NEXT_PUBLIC_SENTRY_DSN` | Sentry | 错误监控 | 🟢 低 |
| `SENTRY_AUTH_TOKEN` | Sentry | 发布跟踪 | 🟢 低 |

### 密钥获取指南

#### 1. Resend API Key 配置步骤

```bash
# 步骤 1: 访问 Resend 控制台
https://resend.com/api-keys

# 步骤 2: 创建 API Key
- 点击 "Create API Key"
- 选择权限范围 (建议: "Send emails")
- 复制生成的 API Key (格式: re_xxxxxxxxxxxxx)

# 步骤 3: 配置域名验证
- 在 Resend 添加域名 7zi.studio
- 配置 DNS 记录 (TXT 记录用于验证)
- 配置 DKIM 记录

# 步骤 4: 更新 .env.production
RESEND_API_KEY=re_xxxxxxxxxxxxx
CONTACT_EMAIL=business@7zi.studio
FROM_EMAIL=noreply@7zi.studio
```

#### 2. GitHub Token 配置步骤

```bash
# 步骤 1: 访问 GitHub Settings
https://github.com/settings/tokens

# 步骤 2: 创建 Personal Access Token
- 点击 "Generate new token" → "Generate new token (classic)"
- 设置过期时间 (建议: 90 days)
- 选择权限: repo (勾选 full control of private repositories)
- 生成 Token (格式: ghp_xxxxxxxxxxxxx)

# 步骤 3: 更新 .env.production
GITHUB_TOKEN=ghp_xxxxxxxxxxxxx
```

#### 3. Sentry 配置步骤

```bash
# 步骤 1: 访问 Sentry 控制台
https://sentry.io/

# 步骤 2: 创建项目
- 选择 "Create Project"
- 选择平台: Next.js
- 项目名称: 7zi-frontend

# 步骤 3: 获取 DSN
- 在项目设置中找到 "Client Keys (DSN)"
- 复制 DSN (格式: https://xxx@sentry.io/xxx)

# 步骤 4: 获取 Auth Token (可选)
- 访问: https://sentry.io/settings/account/api/auth-tokens/
- 创建 token，选择权限: project:releases

# 步骤 5: 更新 .env.production
NEXT_PUBLIC_SENTRY_DSN=https://xxx@sentry.io/xxx
SENTRY_AUTH_TOKEN=your-auth-token
SENTRY_ORG=your-org-slug
SENTRY_PROJECT=7zi-frontend
```

## ⚠️ 安全注意事项

1. **永远不要将 `.env.production` 提交到 Git**
   - 确保 `.gitignore` 包含 `.env.production`
   - 已提交的应该从 Git 历史中移除

2. **定期轮换密钥**
   - GitHub Token 建议每 90 天更换一次
   - Resend API Key 建议定期更换

3. **使用专用密钥**
   - 不要在多个环境共用同一个 API Key
   - 生产环境使用专用密钥，限制权限范围

4. **密钥权限最小化**
   - GitHub Token 只授予必要的 repo 权限
   - Resend API Key 只授予邮件发送权限
