### 1. CI/CD 流水线优化

#### 创建文件

- `.github/workflows/ci-optimized.yml` - 优化后的 CI workflow
- `.github/workflows/cd-canary.yml` - 支持 Canary 部署的 CD workflow

#### 优化措施

**缓存优化**

```yaml
# 多层缓存策略
- npm cache (via actions/setup-node)
- node_modules cache (with hash-based key)
- Next.js build cache (.next/cache)
- Docker layer cache (GHA + registry)
- Playwright browsers cache
```

**并行化构建**

```yaml
# 并行执行的任务矩阵
strategy:
  matrix:
    include:
      - name: Security Audit
      - name: Dependency Check
      - name: License Check
```

**增量构建**

```yaml
# Next.js 缓存复用
cache-from: type=gha,scope=${{ github.ref_name }}
restore-keys: ${{ runner.os }}-nextjs-
```

**优化效果预估**
| 指标 | 优化前 | 优化后 | 提升 |
|------|--------|--------|------|
| npm install | 2-3 分钟 | 30-60 秒 | **60-75%** |
| Next.js 构建 | 5-8 分钟 | 2-4 分钟 | **50-60%** |
| Docker 构建 | 3-5 分钟 | 1-2 分钟 | **60-70%** |
| **总构建时间** | 10-16 分钟 | **4-7 分钟** | **55-65%** |

### 2. 灰度发布方案设计

#### 创建文件

- `scripts/deploy/canary-deploy.sh` - Canary 部署脚本
- `scripts/deploy/deploy.sh` - 统一部署入口
- `scripts/deploy/rolling-deploy.sh` - 滚动更新脚本
- `scripts/deploy/collect-metrics.sh` - 监控指标收集
- `docs/CANARY_DEPLOYMENT_STRATEGY.md` - 灰度发布策略文档

#### 部署策略对比

| 策略           | 适用场景         | 停机时间 | 风险控制   | 回滚速度  |
| -------------- | ---------------- | -------- | ---------- | --------- |
| **Canary**     | 生产环境（推荐） | 0 分钟   | ⭐⭐⭐⭐⭐ | 2-5 分钟  |
| **Blue-Green** | 紧急修复         | 0 分钟   | ⭐⭐⭐⭐   | 1-2 分钟  |
| **Rolling**    | 单服务器         | <30 秒   | ⭐⭐⭐     | 5-10 分钟 |
| **Quick**      | 热修复（需审批） | <1 分钟  | ⭐⭐       | 5-10 分钟 |

#### 流量分配策略

**阶段式发布（推荐）**

```
阶段 1: 5% 流量 → 30 分钟监控
阶段 2: 15% 流量 → 30 分钟监控
阶段 3: 50% 流量 → 60 分钟监控
阶段 4: 100% 流量 → 完成
```

**流量分配维度**

1. **用户比例** - 按用户 ID 哈希分配
2. **地区维度** - 按地理位置逐步开放
3. **用户组维度** - Beta 用户、内部用户优先

### 3. 监控指标设计

#### 关键指标 (KPI)

| 指标           | 阈值     | 告警条件             | 回滚触发          |
| -------------- | -------- | -------------------- | ----------------- |
| 错误率         | < 5%     | > 5% 持续 5 分钟     | > 10% 立即回滚    |
| 响应时间 (P95) | < 2000ms | > 2000ms 持续 5 分钟 | > 5000ms 立即回滚 |
| CPU 使用率     | < 80%    | > 80% 持续 10 分钟   | > 95% 立即回滚    |
| 内存使用率     | < 85%    | > 85% 持续 10 分钟   | > 95% 立即回滚    |

#### 监控数据源

- Nginx 日志（请求量、错误率、响应时间）
- Docker Stats（CPU、内存、网络）
- 应用 API（健康状态、自定义指标）
- 系统监控（负载、连接数、磁盘）

---

### 4. 快速回滚机制

#### 自动回滚条件

```bash
# 触发自动回滚的场景
- 错误率 > 10%（立即）
- 响应时间 > 5000ms（5 分钟）
- 健康检查连续失败 3 次（立即）
- 容器崩溃且重启失败（立即）
```

#### 手动回滚命令

```bash
# 标准回滚
./scripts/deploy/rollback.sh

# 强制回滚（跳过确认）
./scripts/deploy/rollback.sh --force

# 切换到备份容器（最快）
docker start 7zi-frontend-backup
```

**回滚时间**

- Canary: 2-5 分钟
- Blue-Green: 1-2 分钟
- Rolling: 5-10 分钟

## 🚀 使用指南

### 1. 灰度发布（推荐）

```bash
# 标准灰度发布（初始 10%，持续 30 分钟）
./scripts/deploy/deploy.sh canary ghcr.io/.../7zi-frontend:v1.5.0 10 30

# 保守策略（初始 5%，持续 60 分钟）
./scripts/deploy/deploy.sh canary ghcr.io/.../7zi-frontend:v1.5.0 5 60

# 激进策略（初始 20%，持续 15 分钟）
./scripts/deploy/deploy.sh canary ghcr.io/.../7zi-frontend:v1.5.0 20 15
```

### 2. 蓝绿部署

```bash
# 快速切换
./scripts/deploy/deploy.sh blue-green ghcr.io/.../7zi-frontend:v1.5.0
```

### 3. 滚动更新

```bash
# 单服务器部署
./scripts/deploy/deploy.sh rolling ghcr.io/.../7zi-frontend:v1.5.0
```

### 4. 回滚

```bash
# 标准回滚
./scripts/deploy/rollback.sh

# 强制回滚
./scripts/deploy/rollback.sh --force
```

### 5. 监控

```bash

./scripts/deploy/collect-metrics.sh 300

./scripts/deploy/monitor.sh
```
