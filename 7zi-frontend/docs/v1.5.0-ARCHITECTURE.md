## Architecture Goals

### Primary Goals

1. **Unified Real-time Layer** - Single source of truth for WebSocket communication
2. **Clear Directory Structure** - Logical separation of concerns
3. **Scalable Agent System** - Support for distributed agent scheduling
4. **Type Safety** - Full TypeScript coverage across all layers

### Non-Goals

- Database migration (use existing Prisma schema)
- API versioning (maintain backward compatibility)
- Microservices split (monolith architecture for now)

  'queue:updated': (stats: QueueStats) => void

  // Notification events
  'notification:new': (notification: Notification) => void
  'notification:read': (notificationId: string) => void

  // Room events (v1.4.0)
  'room:joined': (data: { roomId: string; userId: string }) => void
  'room:left': (data: { roomId: string; userId: string }) => void

  // System events
  'system:health': (health: SystemHealth) => void
  'system:maintenance': (info: MaintenanceInfo) => void
}

/**
 * Client → Server Events
 */
export interface ClientToServerEvents {
  // Agent management
  'agent:register': (data: RegisterAgentRequest, callback: (agent: Agent) => void) => void
  'agent:unregister': (agentId: string, callback: (success: boolean) => void) => void
  'agent:heartbeat': (agentId: string) => void

  // Task management
  'task:schedule': (
    request: ScheduleTaskRequest,
    callback: (response: ScheduleTaskResponse) => void
  ) => void
  'task:update': (request: UpdateTaskRequest, callback: (success: boolean) => void) => void
  'task:cancel': (taskId: string, callback: (success: boolean) => void) => void

  // Subscription management
  'subscribe:agents': (callback: (agents: Agent[]) => void) => void
  'subscribe:tasks': (callback: (tasks: Task[]) => void) => void
  'subscribe:queue': (callback: (stats: QueueStats) => void) => void

  // Room events
  'room:join': (roomId: string) => void
  'room:leave': (roomId: string) => void
  'room:send': (data: { roomId: string; message: string }) => void
}

### WebSocket Store (Zustand)

```typescript
// src/lib/websocket/store.ts

import { create } from 'zustand'
import { subscribeWithSelector } from 'zustand/middleware'
import type { Agent, Task, QueueStats, ConnectionState } from './types'

interface WebSocketState {
  // Connection state
  connectionState: ConnectionState
  lastConnected: number | null
  reconnectAttempts: number

  // Agent state
  agents: Map<string, Agent>
  selectedAgentId: string | null

  // Task state
  tasks: Map<string, Task>
  activeTaskId: string | null

  // Queue state
  queueStats: QueueStats

  // Actions
  setConnectionState: (state: ConnectionState) => void
  setAgents: (agents: Agent[]) => void
  updateAgent: (agent: Agent) => void
  removeAgent: (agentId: string) => void
  setTasks: (tasks: Task[]) => void
  updateTask: (task: Task) => void
  setQueueStats: (stats: QueueStats) => void
}

export const useWebSocketStore = create<WebSocketState>()(
  subscribeWithSelector(set => ({
    // Initial state
    connectionState: 'disconnected',
    lastConnected: null,
    reconnectAttempts: 0,
    agents: new Map(),
    selectedAgentId: null,
    tasks: new Map(),
    activeTaskId: null,
    queueStats: { pending: 0, running: 0, completed: 0, failed: 0, total: 0 },

    // Actions
    setConnectionState: state => set({ connectionState: state }),
    setAgents: agents =>
      set(state => {
        const newMap = new Map(state.agents)
        agents.forEach(agent => newMap.set(agent.id, agent))
        return { agents: newMap }
      }),
    updateAgent: agent =>
      set(state => {
        const newMap = new Map(state.agents)
        newMap.set(agent.id, agent)
        return { agents: newMap }
      }),
    removeAgent: agentId =>
      set(state => {
        const newMap = new Map(state.agents)
        newMap.delete(agentId)
        return { agents: newMap }
      }),
    setTasks: tasks =>
      set(state => {
        const newMap = new Map(state.tasks)
        tasks.forEach(task => newMap.set(task.id, task))
        return { tasks: newMap }
      }),
    updateTask: task =>
      set(state => {
        const newMap = new Map(state.tasks)
        newMap.set(task.id, task)
        return { tasks: newMap }
      }),
    setQueueStats: stats => set({ queueStats: stats }),
  }))
)
```

## Technical Decisions

### 1. WebSocket Library Choice

**Decision: Socket.IO (Continue Using)**

| Option                   | Pros                                                         | Cons                             |
| ------------------------ | ------------------------------------------------------------ | -------------------------------- |
| **Socket.IO** (Selected) | Auto-reconnect, rooms, fallback to polling, mature ecosystem | Larger bundle size               |
| ws                       | Lightweight, pure WebSocket                                  | No auto-reconnect, no rooms      |
| Native WebSocket         | No dependencies                                              | No fallback, manual reconnection |

**Rationale:**

- Already integrated in project
- Rooms feature needed for v1.4.0
- Fallback to polling for reliability
- Rich ecosystem and documentation

### 2. Real-time State Synchronization

**Decision: Zustand + Socket.IO Integration**

```typescript
// Pattern: Optimistic Updates with Server Confirmation

// 1. Client emits action
socket.emit('task:schedule', taskRequest, response => {
  if (response.success) {
    // Server confirms, update store
    store.updateTask(response.task)
  } else {
    // Rollback optimistic update
    store.revertTask(taskId)
  }
})

// 2. Optimistic update immediately
store.addTask(tempTask)

// 3. Listen for broadcast updates
socket.on('task:created', task => {
  store.updateTask(task)
})
```

### 3. Error Handling & Reconnection Strategy

**Reconnection Strategy:**

```typescript
// Exponential backoff with jitter
const reconnectionStrategy = {
  // Initial delay: 1 second
  initialDelay: 1000,

  // Maximum delay: 30 seconds
  maxDelay: 30000,

  // Maximum attempts: Unlimited (user can disconnect manually)
  maxAttempts: Infinity,

  // Backoff multiplier
  multiplier: 2,

  // Jitter factor (0-50% of delay)
  jitter: 0.5,
}

// Calculation:
// Attempt 1: 1000ms + random(0-500ms)
// Attempt 2: 2000ms + random(0-1000ms)
// Attempt 3: 4000ms + random(0-2000ms)
// ...capped at 30000ms
```

**Error Categories & Handling:**

| Error Type      | Action             | User Feedback               |
| --------------- | ------------------ | --------------------------- |
| Connection Lost | Auto-reconnect     | Toast: "Reconnecting..."    |
| Auth Failed     | Redirect to login  | Toast: "Session expired"    |
| Server Error    | Retry with backoff | Toast: "Server unavailable" |
| Rate Limited    | Wait and retry     | Toast: "Too many requests"  |

## Risk Assessment

### Technical Risks

| Risk                             | Impact | Probability | Mitigation                                  |
| -------------------------------- | ------ | ----------- | ------------------------------------------- |
| WebSocket connection instability | High   | Medium      | Robust reconnection logic, fallback to REST |
| State synchronization conflicts  | Medium | Medium      | Optimistic updates with rollback            |
| Performance degradation          | Medium | Low         | Pagination, lazy loading, caching           |
| Breaking changes                 | High   | Low         | Maintain backward compatibility             |

### Mitigation Strategies

1. **Connection Stability**
   - Implement heartbeat monitoring
   - Use exponential backoff with jitter
   - Fallback to REST polling after failures

2. **State Consistency**
   - Server is source of truth
   - Optimistic updates with server confirmation
   - Conflict resolution on reconnect

3. **Performance**
   - Limit WebSocket event frequency
   - Use pagination for large datasets
   - Implement client-side caching
